# Leo 风扇控制（LeoMacFanControl）

一个 macOS 原生菜单栏 App，用来监控 CPU 温度 / 风扇转速，并在 Mac mini / MacBook 上**按温度自动升速降温**或**手动固定转速**。

> 适用：Apple 芯片（M1–M5）与 Intel Mac。专为"Mac mini 高负载时风扇不主动升速、机身过热"这类场景设计。

---

## 1. 为什么要自己写（隐私说明）

控速必须给一个进程 **root 权限**。市面上的第三方风扇软件你无法逐行确认它拿到 root 后还做了什么。本工程：

- **全部源码自己写、可逐行审计**，只用 Apple 自带框架（IOKit / Foundation / SwiftUI / ServiceManagement / AppKit / Combine / Darwin）。
- **没有任何网络代码**（不 import 任何网络库，不发任何请求）。你可以全局搜索 `URLSession` / `import Network` / `AF_INET` / `http`，结果为空。全工程只有 `AF_UNIX`（本机进程间通信）这一处 socket。
- 不启动任何子进程、不做动态加载（无 `Process` / `posix_spawn` / `dlopen`）。
- root 守护进程只做一件事：读写 SMC 风扇键。它通过**本机 Unix socket** 接受固定的四条指令（设配置 / 取状态 / 探活 / 停止），不监听任何网络端口。
  - socket 权限为 `root:admin 0660`：只有本机管理员用户（本来就能 `sudo` 的那些人）能下发控速指令，其他用户和沙盒进程都被内核直接拒绝。
  - 之所以不用 `0600`：菜单栏 App 以普通用户身份运行，`0600` 会让它永远连不上守护进程、只能显示"仅监控"。
  - 守护进程对收到的配置一律做范围夹取（转速 0–100%、保护温度 85–110℃），不信任任何外部输入。

---

## 2. 先了解一个现实限制（很重要）

苹果**没有公开的风扇控制 API**。所有控速都靠读写 SMC（系统管理控制器）的私有接口，且在 Apple 芯片上：

- macOS 的 `thermalmonitord` 守护进程默认把风扇锁在"系统模式"，会**拦截/抢回**手动写入。本工程用两段式策略应对：先尝试直接写模式；不行就走逆向出来的 `Ftst` 诊断解锁序列；并由常驻守护进程持续"压住"控制权。
- **各代芯片表现不同**（基于公开逆向资料）：
  - **M1**：通常可直接进入手动模式，成功率高。
  - **M2 / M3**：未充分验证，按 M4 路径尝试。
  - **M4**：部分机型需要 `Ftst` 解锁，本工程已实现。但**实测 Mac mini（Mac16,10, M4）的 SMC 里根本没有 `Ftst` 键**，只能走"直接写模式键"这一条路；如果系统拒绝，就没有别的后手了。
  - **M5**：模式键变成小写 `F0md`、且无 `Ftst`，可直接写——本工程已自动探测大小写。
- 个别新机型可能"写了没反应"（系统强行覆盖）。如果遇到，App 仍可正常**监控**，面板上会明确显示"控速未生效"及原因——这是系统层限制，不是代码 bug。
- ⚠️ **风险**：把风扇设得过低可能导致过热。本工程的自动曲线只会"按需升速"，手动转速也被夹在硬件 `min~max` 区间内，并内置**高温强制满速保护**（默认 ≥100°C，可在面板里 85–110°C 之间调整）。但仍请留意温度，自担风险。

## 3. 架构

```
菜单栏 App (LeoFanControl，普通权限)
  │   · 直接读 SMC 显示温度/转速（只读，无需 root）
  │   · 通过本机 Unix socket 把"模式/曲线/转速"下发给守护进程
  ▼
root 守护进程 (fanhelperd，由 LaunchDaemon 以 root 启动)
  │   · 持有 SMC 连接，跑控速循环（约每 0.7s 重写一次，压住系统抢回）
  │   · Ftst 解锁 + 写风扇模式/目标转速
  ▼
AppleSMC 内核驱动 → SMC 固件 → 风扇
```

- `Sources/FanControlCore/`：共享核心（SMC 通信、数据解码、风扇控制、曲线、IPC 协议）。
- `Sources/LeoFanControl/`：菜单栏 GUI。
- `Sources/fanhelperd/`：root 守护进程。
- `Scripts/`：构建与安装脚本。

## 4. 温控算法（自动模式怎么决定转速）

每 0.7 秒一个控制周期，依次做四件事（实现见 `Sources/FanControlCore/FanCurveEngine.swift`）：

**① 取温度。** 枚举 SMC 全部键，挑出 CPU 核心簇传感器（Apple 芯片是 `Tp..` / `Te..`，Intel 是 `TC..`），
算出两个量：**核心平均温度**（喂给曲线）和**单核峰值温度**（喂给高温保护）。

**② 低通平滑。** 对两个量各做一阶 EMA，时间常数 8 秒。
这一步不能省：Apple 芯片的单核传感器噪声极大，实测 M4 Mac mini **空闲状态下**单核峰值就能在
一秒内从 74°C 跳到 97°C，直接拿瞬时值去查曲线，风扇会一直抖。

**③ 查曲线。** 用平滑后的平均温度做**分段线性插值**，得到目标转速占 `[min, max]` 的比例。
曲线在整个定义域上连续（低于首点取首点、高于末点取末点、中间线性过渡），不存在硬跳档。
Apple 芯片和 Intel 的温度量级完全不同，所以两套曲线分开校准，运行时按 `hw.optional.arm64` 自动选择。

Apple 芯片曲线（横轴＝平滑后的核心平均温度）：

| 档位 | 控制点（温度°C → 比例） |
|---|---|
| 静音 | 76→0.00, 82→0.18, 88→0.45, 94→0.75, 100→1.00 |
| 均衡 | 73→0.00, 79→0.22, 85→0.50, 91→0.80, 97→1.00 |
| 强力降温 | 70→0.00, 76→0.30, 82→0.60, 88→0.85, 94→1.00 |

校准依据是 M4 Mac mini 实测：空闲核心平均 ≈ 71°C，10 线程满载 ≈ 80°C。
（Intel 曲线仍按 40–90°C 的传统量级，见源码。）

**④ 升降速限速（滞回）。** 转速不会直接跳到目标值，而是限速逼近：
**升速最快 30%/秒，降速最快 5%/秒**。降速刻意比升速慢 6 倍，这就是滞回——
风扇转起来会把 CPU 吹凉，吹凉了曲线又要求降速，没有阻尼就会来回振荡。
实测阶跃升温约 26 秒到满速，阶跃降温约 20 秒回到最低。

**高温保护**独立于上面四步，优先级最高：平滑后的**单核峰值**温度 ≥ 阈值（默认 100°C）就强制满速、
无视当前模式，且**跳过限速立即拉满**；要降到 `阈值 − 5°C` 才解除。触发和解除用不同阈值（滞回带宽 5°C），
避免在阈值附近反复横跳。

## 5. 编译与安装（按顺序）

前置：macOS 13+、已装 Xcode（含命令行工具）。

### 第 1 步：编译并打包 GUI

在项目根目录（普通用户，不用 sudo）：

```bash
./Scripts/build-app.sh
```

生成 `LeoFanControl.app`。可把它拖进 `/Applications`。双击即可运行（菜单栏出现风扇图标 + 温度）。
此时已经能**监控**温度和转速。

> 也可以直接用 Xcode 打开：`File ▸ Open` 选中项目根目录里的 `Package.swift`，选 `LeoFanControl` scheme 运行。

### 第 2 步：安装 root 守护进程（控速才需要）

```bash
# 1) 先编译守护进程（普通用户）
swift build -c release --product fanhelperd

# 2) 再以 root 安装并启动（会注册为开机自启的 LaunchDaemon）
sudo ./Scripts/install.sh
```

装好后，App 面板右上角会从"仅监控"变成"守护进程运行中"，这时"自动温控 / 手动固定"才会真正生效。

## 6. 使用

点击菜单栏图标弹出面板：

- **控制模式**：
  - `系统自动`：交还给 macOS（最安全，默认）。
  - `自动温控`：按曲线随温度自动升降速。
  - `手动固定`：用滑块设定一个固定转速百分比。
- **温控档位**（自动模式下）：`静音 / 均衡 / 强力降温`。越强越早提速、越压温度。
- **手动转速**（手动模式下）：0–100%，对应风扇最低～最高转速。
- **高温保护**：85–110°C 可调，默认 100°C。任何模式下超过它都强制满速。
- **开机自动启动**：登录时自动拉起 App（`SMAppService`）。
  - 守护进程已经是开机自启（LaunchDaemon），所以即使没开 App，上次的控速配置也会在重启后自动恢复。

面板顶部同时显示**核心平均温度**（大字，也是自动曲线的输入）和**单核峰值温度**（小字，高温保护的输入）。
两者差 15–25°C 是 Apple 芯片的正常现象，不是读数错误。

针对你的需求（"Mac mini 跑 AI 任务发烫"）：建议选 **自动温控 + 强力降温**。

---

## 7. 卸载

```bash
sudo ./Scripts/uninstall.sh
```

会停止并移除守护进程，并把风扇**交还给 macOS 自动控制**。GUI 直接删除 `LeoFanControl.app` 即可；如开了自启，先在面板里关掉开关。

## 8. 故障排查

- **面板一直显示"仅监控"**：守护进程没装或没起来。检查：`sudo launchctl print system/com.leo.fancontrol.helper`，看日志：`sudo tail -f /Library/Logs/LeoFanControl/fanhelperd.log`。
- **温度显示 `--`**：读不到 CPU 传感器（极少见）。该机型传感器键可能特殊，可在 issue 里反馈具体型号。
- **改了转速没反应**：面板底部会显示具体原因。若提示"系统拒绝进入手动模式"，说明命中了前述系统限制，
  守护进程会按 2/4/8…60 秒退避重试，不会把 CPU 占满。
- **面板显示"仅监控"但守护进程确实在跑**：确认你的账号在 `admin` 组里（`id -Gn | grep admin`）。
  socket 是 `root:admin 0660`，非管理员账号连不上。
- **`swift build` 报缺少命令行工具**：先 `xcode-select --install`。
